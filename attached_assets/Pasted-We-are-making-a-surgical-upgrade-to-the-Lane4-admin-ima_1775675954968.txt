## What we now know

The current candidate pipeline is centered in:

* `harvest_candidates.py`

The request path is:

* `/api/ua/fetch-candidates`
* `main.py` route
* `harvest_candidates.py: fetch_candidates(school, ...)`
* results merged into `static/candidates_manifest.json`

Current sources include:

* official school website crawl
* site-restricted DuckDuckGo search on school domain
* DuckDuckGo general fallback
* Wikipedia / Wikimedia fallback

Google CSE code exists but is inactive because keys are not set.
Pexels code exists but is dead code and should remain unused unless explicitly requested later.

## 2. Tighten official-domain sourcing

Official-domain results should dominate.

Improve the crawl of official school / athletics pages first.

Keep fallbacks, but demote them.

### Desired order of trust:

1. official school site and official athletics site
2. site-restricted search on official domains

4. Wikipedia / Wikimedia fallback

## 3. Reject junk much harder

Strengthen filtering so the pipeline is much less likely to return:

* logos
* seals
* maps
* icons
* renderings
* placeholders
* tiny images
* distorted banners
* obvious CMS thumbnail derivatives
* black and white / historical images
* generic headshots / portraits
* irrelevant action images
* duplicate or near-duplicate assets

In particular:

### Add stronger penalties or rejection for:

* URL tokens like `thumb`, `thumbnail`, `small`, `medium`, `crop`, `banner`, `header`, `tile`, `card`, `sprite`, `logo`, `seal`, `map`, `placeholder`, `rendering`
* suspicious aspect ratios that indicate banners or page chrome
* very low resolution images even if they technically pass the current minimum
* image URLs that look like transformed/cropped derivatives when a larger original is available

Do not become so aggressive that we kill all candidates.
Be smart, not reckless.
